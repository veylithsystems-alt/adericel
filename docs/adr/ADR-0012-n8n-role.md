# ADR-0012: n8n orchestrates; it does not decide

**Status:** Accepted · **Date:** 2026-09-09

## Context

n8n is the orchestration layer and Deliverable B is a single importable export
of it. The risk is well known to anyone who has watched a workflow tool grow
inside an organisation: it starts as glue and becomes the system. Business logic
moves into Function nodes because that is where it is quickest to write, and
eventually the real rules live in a JSON blob that has no tests, no types, no
review history and no way to be replayed.

For Adericel specifically, the failure would be n8n becoming a second
implementation of the Truth Engine — one that disagrees with the first.

## Decision

**Workflows may sequence, schedule, retry, transform and notify. They may not
decide anything about assurance.**

Concretely, and enforced by `workflows/n8n/validate.ts`:

- No workflow computes an assurance state. Assessment happens by calling the
  API, which calls the Truth Engine.
- No workflow writes to the database. There is no PostgreSQL node in the export;
  every state change is an authenticated API call, so authorisation, tenant
  isolation, audit and idempotency all apply.
- No workflow holds a credential in its definition. Endpoints come from `$env`;
  authentication is a named n8n credential created after import.
- No workflow approves an action. An n8n execution is not a person (ADR-0015).
- Every workflow that changes state names an error workflow, so a failure
  produces a recorded, describable state rather than silence.

Adericel is fully functional with n8n stopped. Scheduled collection and
reassessment also exist as jobs in the Adericel worker; n8n is the layer that
makes them _observable and editable by an operator_, not the layer that makes
them happen.

## Alternatives considered

**Build orchestration into the worker only, no n8n.** Simpler, fewer moving
parts, and it was the design until the requirement for operator-editable
integration flows was weighed. MSP operators need to wire Adericel to whatever
ticketing, chat and RMM tooling their customers already run, and doing that as a
code change per customer does not scale for a small company.

**n8n as the primary application layer.** Explicitly ruled out by the brief and
correctly so — see the failure mode above.

**Temporal.io from the start.** The right long-term answer for durable execution
and the stated direction of travel. Rejected as the starting point because it
requires workflows to be written in code, which removes exactly the operator
editability n8n was chosen for, and because a Temporal cluster does not fit
alongside PostgreSQL, Redis and Ollama on a 16 GB machine.

The migration path is deliberately open: because workflows only sequence API
calls, a workflow's logic is a list of calls with retry and compensation
semantics — which is precisely what a Temporal workflow expresses. Moving one
does not require the Truth Engine, the API or the data model to change. That
property is the reason this boundary is drawn where it is.

## Consequences

- Some things are more verbose in n8n than they would be in a Function node.
  Accepted; a Code node that "just normalises this one field" is how the
  boundary erodes.
- The export is generated by TypeScript (`workflows/n8n/build.ts`) rather than
  hand-maintained. Hand-written JSON at this size cannot be reviewed and drifts
  from the API it calls.
- CI validates structure and safety, and fails on drift between the committed
  JSON and the builder's output.
- Workflow executions are not the audit trail. The audit trail is in Adericel,
  because n8n's execution history is pruned.

## Security implications

n8n holds an Adericel API key and therefore has exactly the authority that key
was granted — no more. The key is issued to a service principal whose
permissions exclude approval, so a compromise of the n8n instance cannot
approve an action. That is the single most important consequence of this
decision.

Workflows read configuration from `$env`, which requires
`N8N_BLOCK_ENV_ACCESS_IN_NODE=false`. That is a real widening: any workflow on
that instance can read any variable in the environment. It is accepted on the
basis that the instance is single-tenant to the operator and its environment
holds no customer credentials — and it is the reason n8n is served on its own
hostname rather than inside Adericel's origin.

## Operational implications

The export imports into a clean instance using core nodes only; no community
packages are required. Five workflows activate on import — webhooks, schedules
and the error handler — and the rest are called as sub-workflows.

## Migration implications

Workflow by workflow, an n8n workflow can be replaced by a Temporal workflow
that makes the same API calls, with both running side by side during the
transition since every operation is idempotent (ADR-0016). No data migration is
involved, and there is no point at which both must be switched over at once.
